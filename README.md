# 学生管理系统：咨询与试听切片

这是面试作业的本地演示原型。设计、业务假设和计划中的完整模型见 [DESIGN.md](DESIGN.md)；目前实现的范围限于 admin 工作台、咨询、试听与试听后跟进。

## 业务流程

面向教育机构的一线管理员，集中管理从家长咨询到试听后跟进的过程：

1. 登记学生、家长联系方式和咨询需求，创建咨询线索。
2. 为学生安排试听，记录试听时间、意向和课堂备注。
3. 对有兴趣或仍在考虑的学生生成跟进待办；管理员记录沟通结果，并按需安排下次联系。
4. 根据沟通结果记录报名意向或流失，保留咨询、试听和跟进历史。

“有报名意向”仅是人工记录的业务状态，不表示已收款、创建正式报名或分配课时。数据库沿用旧值 `active`，学生详情接口将其表示为 `enrollment_intent`。

## 已实现功能

- 管理员登录与工作台：展示待跟进、逾期任务、今日试听和负责的学生数量。
- 咨询管理：新建线索，按学生姓名搜索和分页浏览咨询，查看学生及家长资料。
- 试听管理：安排试听、记录结果与课堂备注，并阻止同一学生重复安排有效试听。
- 取消试听：记录取消原因和操作人，保留原试听及改期记录，咨询可继续安排试听。
- 学生资料：修改学生及家长联系方式；已结束咨询的学生再次咨询时可新建记录，并恢复跟进状态。
- 老师分配与改期：管理员可创建老师账号，学生可暂不分配老师；安排试听或学生详情中可指定老师，并保留老师变更与试听改期历史。
- 跟进管理：按试听意向生成待办，记录沟通、下次联系时间及报名或流失结果，查看历史记录。
- 学生目录与任务中心：按学生汇总最近咨询，支持状态筛选、搜索和 CSV 导出；任务可按全部、逾期、今天和即将到期筛选。
- 重复学生提醒：新建咨询时按当前管理员名下的家长电话，或学生姓名与家长姓名组合识别疑似重复；管理员可返回修改，或明确确认后保留为独立历史记录。
- AI 跟进建议：基于课堂备注生成结构化建议；未配置模型或调用失败时使用规则建议。
- 业务权限与时间：管理员只能访问自己负责的学生；试听和跟进时间按墨尔本时区处理，包括夏令时校验；同一老师同一时刻不能重复安排试听。

## 技术选型

- 前端：React、TypeScript、Vite。
- 后端：Node.js、TypeScript、SQLite。
- AI：可配置的 OpenAI 兼容接口，使用 JSON Schema 校验结构化响应。
- 测试：Node.js 内置测试运行器，使用独立数据库和本地模拟模型服务。

## 运行

需要 Node.js 24 和 npm。使用两个终端：

```powershell
npm install
npm run seed
npm run dev:api
```

```powershell
npm run dev:web
```

浏览器打开 Vite 显示的本地地址，默认 `http://127.0.0.1:5173/`。演示账号为 `amy@austin.edu`，密码 `demo123`。seed 仅在用户表为空时生成数据，不会重置已有数据库。SQLite 文件保存在 `data/student-management.db`，不会提交到 Git。

`npm run build` 构建前端并编译后端；`npm run type-check` 单独执行类型检查。开发服务器使用 Vite 代理将 `/api` 转发至本机 3001 端口。`npm start` 启动已编译的 API，不托管前端静态文件。

`npm test` 在系统临时目录创建独立数据库，启动隔离 API 和本地模拟模型服务，覆盖权限、状态流转、历史数据、重复提交、夏令时与 AI 降级；测试不使用当前演示数据库。

## 配置

服务进程读取环境变量，支持项见 `.env.example`；目前不会自动加载 `.env` 文件。如需启用 LLM，请在启动 API 的终端设置 `LLM_API_URL`（完整的 OpenAI 兼容 chat completions 地址）、`LLM_API_KEY` 和 `LLM_MODEL`。所选 provider 必须支持 `json_schema` 响应格式。没有配置或调用失败时，会使用规则建议。课堂备注会发送给所配置的 provider；使用真实学生资料前需确认相应授权和数据处理方式，不要提交密钥。

`ALLOWED_ORIGINS` 是允许浏览器写操作的来源列表；更换前端地址时需同步设置。HTTPS 环境需设置 `COOKIE_SECURE=true`。登录限流和模型熔断仅在单进程内生效。

端口冲突时，可为 API 设置 `PORT`，为 Vite 设置 `VITE_API_PROXY` 指向该 API，并将 Vite 实际地址加入 API 的 `ALLOWED_ORIGINS`。

## 当前限制

- 演示账号和弱密码仅供本机测试；登录限流和来源检查不能代替生产级身份与部署安全审查，不应直接公开部署。
- 工作台和学生目录只展示当前 admin 的学生与咨询；教师工作台、跨管理员全员列表、手动跳过任务、正式订单、班级和课时尚未实现。老师账号目前仅供分配使用，尚无教师工作台；历史试听若未记录老师，不会推测补填。
- 同一学生存在未结束的咨询、试听或跟进待办时，需先完成现有流程才能新增咨询；原历史结论不会被覆盖。
- 重复提醒是人工确认机制，不会自动合并学生、删除历史或跨管理员匹配记录。
- LLM 的成功、异常和超时测试使用本地模拟服务；未配置真实 provider 或验证真实模型调用。
- 尚未完成完整无障碍检查和生产部署。种子数据为虚构演示数据，仅在数据库没有用户时写入；现有数据库不会被覆盖或扩充。
